# Go Epic - Project Guide

## PR Traceability
Every pull request:
1. ends its title with the **branch session ID** as `- [SessionID]` (the trailing characters of the branch name, e.g. `ofxb07` from `claude/charming-planck-ofxb07`);
2. shows it in the body (`Session: ofxb07`);
3. carries the PR Checklist below.

## Overview
Go Epic is the Week board, Focus mode and Floating Canvas of Epic Manager (`giannifontanot/epic-manager`), rebuilt on Firebase with no server of its own. Only those three screens exist on purpose: no seed editor, no variants, no sync queue. The owner is Gianni.

- **Stack:** Angular 22 (standalone components, signals, new control flow, zoneless), TypeScript strict, Firebase JS SDK 13 (Auth + Firestore), Firebase Hosting, Vitest.
- **Cost:** must stay on the free **Spark** plan: no Cloud Functions, no Cloud Run, nothing that needs the Blaze plan.
- **Offline:** Firestore's persistent multi-tab cache is the offline layer; writes show at once and sync when the network is back. Never add a hand-made sync queue.
- **PWA:** installable app (`public/manifest.webmanifest`, icons in `public/icons/` drawn from `public/icons/icon.svg`, `apple-touch-icon.png` and iOS meta tags in `src/index.html`). The Angular service worker (`ngsw-config.json`, production builds only) caches the app shell so it opens offline; it never caches Firestore/Auth traffic, and navigations to `/__/**` (Firebase's reserved paths) bypass it. `firebase.json` serves `ngsw-worker.js`, `ngsw.json`, the other worker scripts and the manifest with `no-cache` (that rule must stay after the immutable `**/*.@(js|css)` rule: Hosting applies matching header rules in order, the last one wins). When a new version has downloaded, `App` shows an update bar (`SwUpdate` VERSION_READY → "Update" reloads; the whole bar flashes a soft yellow halo so it is noticed (`update-halo`, a still halo under reduced motion); checks every 30 min; an unrecoverable state reloads).

## Data (Firestore)
```
users/{uid}/week/{DAY}         { blocks: Block[] }                 DAY = MONDAY…SUNDAY
users/{uid}/days/{YYYY-MM-DD}  { done: { [taskId]: millis },       the day's task states (local date), status.model:
                                 status: { [taskId]: state } }     done/late keep `done`; late/progress/skipped in `status`
users/{uid}/library/tree       { nodes: LibNode[] }                the task library (Floating Canvas)
users/{uid}/todos/{id}         Todo                                Capture's tasks (todo.model)
```
- `Todo { id, title, date: 'YYYY-MM-DD'|null, time: 'HH:mm'|null, done: millis|null, created: millis, repeat: Day[], doneOn: { [date]: millis } }` (Gianni): a task with `repeat` days (Mo…Su) comes back every week on those days and is checked per date in `doneOn` (never Finished); a single task open on an earlier day **rolls over** (`overdueTodos`) to the top of today's column, with a red edge and "from Mon 9", and leaves its old day; checking it moves its date to the day it was ticked, so the checked note stays there (`checkTodo`). Capture holds **tasks**, one-off to-dos with a day and maybe an hour and a check, **not Activities** (the library). `sanitizeTodo` on the way in.
- **Names (Gianni, as in Epic Manager's nomenclature):** the five levels are shown as **Area → Epic → Feature → Story → Activity** (ES **Actividad**, feminine: la Actividad, una Actividad nueva) ("Activity" replaces Task: Gianni found "Beat" confusing and "Action" unfriendly; "Story" replaces User story; a Story is shaped by its Activities, step by step). Story is feminine in Spanish (la Story). The code keeps `kind: 'story' | 'task'`.
- `LibNode { id, kind: 'area'|'epic'|'feature'|'story'|'task', title, parentId: string|null, color, created? }`: `created` (tasks only, millis, written only when present: Firestore refuses undefined) is when a task was captured or made (Capture, Canvas, Week details); its **paper ages** from then (`paperAge`: fresh under 5 days, parchment 5–20, old stained paper from 21, Epic Manager's textures in `public/paper/`), in the Capture list, on its week cards and in the activity picker, so a neglected idea shows it (Gianni); a task without `created` (older, template) keeps its pastel. Five levels, Area → Epic → Feature → Story → Activity (task), each parent of the kind above (`PARENT_KIND`). `parentId` null = an area (the top) or an object waiting in **Free Space** (never an epic). Every task exists once in the library; a container can be deleted only when empty, a task always (its week places go on Save).
- `Block { id, name, start: 'HH:mm'|null, end: 'HH:mm'|null, tasks: Task[] }`: the start anchors the first task, later starts cascade by minutes; the end is a hard limit (the tasks' minutes never pass `end - start`).
- `Task { id, title, minutes, color: string|null, active, ref: string|null }`: `color` null = automatic pastel (`blockColors`: FNV-1a of the title, never like the card above). `ref` = the library task this card schedules (one library task can sit in many blocks); the library is the truth for its title and colour (`followLibrary`).
- `firestore.rules`: each user reads/writes only `users/{uid}/**` (week, days, library and todos). Update the rules with any new collection.
- Firestore refuses `undefined`: `WeekStore` sanitizes every block on the way in and out.
- `WeekStore.setBlocks` writes a whole day; an echo of an older local write must not undo a newer one (`pending` queue per day). Keep that when touching the store.

## Code map
- `src/app/core/week.model.ts`: types and **pure** rules (clock parsing 24h `HH:mm`, cascade, windows, free time, colours, now-line, timeline). Put new rules here with specs.
- `src/app/core/week.store.ts`: the signed-in user's week + today's states (`marks`, `status(id)`, `setStatus`), the day history for Progress (`watchHistory`), clock signal (15s).
- `src/app/core/status.model.ts` (pure, with specs): **States** as in Epic Manager: To do, Done, Late (done, not on time), In progress, Skipped. Old documents with only `done` still read as Done. **Progress**: every active task of the week is a habit (grouped by its library `ref`, else its title) with its last 14 days drawn and its **streak** (counted over the last 90 days read; "n+ days" when it may go back further): finished days (done/late) count, skipped and unplanned days pause it, a missed day ends it; today still open never breaks it; a habit's history starts the first day it was ever marked (no misses before). Uses the current week plan for past days.
- `src/app/core/dialog.ts`: **every window opens growing out of the point the user pressed and closes shrinking back into it** (Gianni's rule): `openDialog(dialog)` / `closeDialog(dialog)` (closing: it shrinks home fully visible and fades only the last step, `closeFrames`; **opening is its exact mirror**, Gianni: the same 300 ms, the same frames backwards and the time-reversed curve, ease-in `(.4,0,1,1)` ↔ ease-out `(0,0,.6,1)`; the backdrop fades; nothing under reduced motion; Esc closes the same way unless the dialog handles it, `escape: false`). Never call `showModal()`/`close()` directly; components removed by `@if` animate out first, then emit.
- `src/app/core/tilt.ts` (`tiltOf`, `pileShift` pure, with specs): **weighted buttons**, a visual detail only: when the phone leans (`deviceorientation` gamma, portrait only, 4° dead zone, full at 60°) every button leans up to 5° and slides towards the lower side by 55% × lean of its free room to that edge (`--tilt-rl`/`--tilt-rr`, measured at rest every 400 ms while leaning, up to the nearest box that clips it: a panel with overflow, a dialog, else the screen), so the farther ones travel more and they **pile up on top of each other** without leaving their panel (Gianni); upright they spring back (a small overshoot). **Everything has weight** (`TILT_BODIES`, the same list as `html.tilt :is(…)` in styles.css): blocks, week cards, Canvas objects, habits, Capture notes and the picker's cards lean (30% of the buttons' angle, since they nest) and slide the same way; a body inside another (a card in its block, a button on a card) slides within that body's box, so nested slides add up without ever passing the clipping edge; the room is measured from each body's upright edges and leaves free the distance its corners swing when it leans (`leanSwing`: a tall card turning 1.5° reaches several px past its sides); a Canvas object keeps its place on this device in `--ox`/`--oy` (canvas-node) and the slide is added to it. The root's registered `--tilt-r`/`--tilt-k` glide and buttons follow through `rotate`/`translate` (styles.css). Menu switch "Weighted buttons" (`go-epic-tilt`, on by default); iPhone/Chrome ask for motion permission on the first tap (a refusal turns it off). Nothing under reduced motion.
- `src/app/core/auth.service.ts`: Google sign-in (popup, redirect fallback).
- `src/app/core/firebase.ts` + `src/app/firebase.config.ts`: Firebase init; config values are public (not secrets). On localhost, `localStorage['go-epic-emulators']='1'` uses the emulators with project `demo-go-epic`.
- `src/app/core/i18n.ts`: EN/ES labels (`I18n.t`); every key needs both languages (a spec checks it).
- `src/app/pages/week-board/`: Week board, `TaskDialog` (Floating Canvas look: Delete top, Cancel/Done bottom, edits a draft), `TransferDialog` (white Copy/Move card). Top: title · ✓ Finish (centred, only while arranging) · 💡 Capture at the right, and while arranging the **Aa / AV steppers** (as in Epic Manager, the change shows at once on the cards: `core/text-settings.ts`, `go-epic-text` on this device; Aa sets the activities' and stories' text 13/15/17/19.5/22.5px as `--act-fs`, every other label follows gently through `--esc` = 1 + 60% of the change (`textScale`), AV sets −0.02…0.1em as `--act-ls`, the rest of the app half of it, `--app-ls`); on this page the floating ✎ **arranges the week** (`CaptureUi.fab`, hidden while arranging) instead of opening Capture; edit mode **grows out of the ✎** in a widening circle and Finish shrinks it back into the same point (`toggleArrange`: a View Transition, `html.vt-grow`/`vt-shrink`, 300 ms with the dialogs' mirrored curves; a plain switch where the browser has none or under reduced motion). ## Conventions
- Standalone components, signals (`signal`, `computed`, `input`, `output`), `@if/@for`; no NgModules, no RxJS state.
- Phones first: tap targets ≥ 40px, inputs 16px (no iOS zoom), safe-area insets, one day at a time ≤ 820px.
- Dialogs are native `<dialog>` with `showModal()`; backdrop clicks via `isBackdropClick`.
- Respect `prefers-reduced-motion`.

## PR Workflow (AI Assistant)
The AI assistant **never runs the test suite** itself (typecheck, builds and emulator checks are fine). **GitHub Actions runs it**: `.github/workflows/ci.yml` (Node 22, `npm ci`, `npm test -- --watch=false`, `npm run build`) on every pull request and on main. After pushing: open the PR and comment `@codex review`; fix every Codex finding and ask Codex again; **do not ask Gianni to run tests** (a manual check on his phone only when one is really needed, asked once Codex is clean). Merge only when Codex has no open findings and the **CI check is green on the exact current HEAD**. Angular 22 needs Node ^22.22.3 || ^24.15.0 locally.
