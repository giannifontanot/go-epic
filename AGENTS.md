# Go Epic - Project Guide

## PR Traceability
Every pull request:
1. ends its title with the **branch session ID** as `- [SessionID]` (the trailing characters of the branch name, e.g. `ofxb07` from `claude/charming-planck-ofxb07`);
2. shows it in the body (`Session: ofxb07`);
3. carries the PR Checklist below.

## Overview
Go Epic is the Week board, Focus mode and Floating Canvas of Epic Manager (`giannifontanot/epic-manager`), rebuilt on Firebase with no server of its own. Only those three screens exist on purpose: no seed editor, no variants, no sync queue. The owner is Gianni.

- **Stack:** Angular 22 (standalone components, signals, new control flow, zoneless), TypeScript strict, Firebase JS SDK 13 (Auth + Firestore), Firebase Hosting, Vitest.
- **Cost:** must stay on the free **Spark** plan: no Cloud Functions, no Cloud Run, nothing that needs the Blaze plan.
- **Offline:** Firestore's persistent multi-tab cache is the offline layer; writes show at once and sync when the network is back. Never add a hand-made sync queue.
- **PWA:** installable app (`public/manifest.webmanifest`, icons `public/icons/go-epic-<size>.png`, `apple-touch-go-epic.png` and `favicon.png`, all drawn by `tools/make-icons.py` (Pillow + fontTools) in the Get Go Epic page's look (Gianni): its off-white page, its wordmark's Cinzel Decorative Black (read from `public/get/cinzel-decorative-900.woff2`), "Go" in navy over "Epic!" in the wordmark's gold, as big as the maskable safe zone allows, so Go Epic is read at a glance among the phone's icons (Gianni); every theme's manifest lists the same icons, and new names make installed apps pick them up; iOS meta tags in `src/index.html`). **The root `/` is the Get Go Epic page, the app lives behind it** (Gianni: getgoepic.com/ must open the page, not /get): the build writes the app shell as `app.html` (angular.json `index.output`, never `index.html`, since Hosting would serve a static `/index.html` before any rewrite), and `firebase.json` rewrites `/` to `/get/index.html` and everything else to `/app.html`. The page's first script sends the installed app (display-mode standalone, fullscreen or minimal-ui, or iOS `navigator.standalone`) and anyone signed in to the app in that browser (`go-epic-signed-in` in localStorage, set and cleared by `AuthService` as Firebase reports the user, or a Firebase session an older version saved, `firebase:authUser:*` in IndexedDB or localStorage, looked up by both scripts and then remembered; Gianni: a signed-out visitor must see the page, never the sign-in screen) straight on to `/app`, which the router turns into the Week board at `/`. When the service worker answers `/` with the shell instead, the shell's first script does the reverse: anyone neither installed nor signed in goes to `/get/` and `main.ts` does not start the app (`window.goEpicGate` resolves false; no answer within 1.5 s starts it); never on localhost. The page's download and Open Go Epic links go to `/app`. The Angular service worker (`ngsw-config.json`, production builds only, index `/app.html`) caches the app shell so it opens offline; it never caches Firestore/Auth traffic, and navigations to `/__/**` (Firebase's reserved paths) bypass it. `firebase.json` serves `ngsw-worker.js`, `ngsw.json`, the other worker scripts and the manifest with `no-cache` (that rule must stay after the immutable `**/*.@(js|css)` rule: Hosting applies matching header rules in order, the last one wins). When a new version has downloaded, `App` covers the screen (Gianni: impossible to resist): a native modal `dialog.update-overlay` (opened with `openDialog`, so it sits in the top layer above any other open window and traps focus; Esc does nothing), a dark backdrop with a card in the middle, "There is a new version" and one huge button, "Tap to update" / "Presiona para actualizar" (`.update-overlay`, `.update-button` 96px tall, **sober**: flat, no halo, no glow, no flashing or breathing (Gianni)), and above it **what is new** (Gianni: so he knows what to look for): the lines of `public/changes.json` grouped by **version** (`v`: one published PR, all its lines share it), one version at a time, opening on the newest, with ‹ › arrows at the top to step back through every earlier version (Gianni: to see what each update window said), a label "Version n · date" and a "New" tag on the versions newer than the running build (`core/changes.model.ts` `versionPages`: the file is bundled, so a build knows its own last `v`, and the window fetches `/changes.json` fresh past the service worker and every cache, `ngsw-bypass`, no-cache in `firebase.json`, falling back to the bundled history; the lines scroll inside the card); it **wears the theme** (Gianni: it looked out of place): the card has the windows' thin edge, the button is the theme's primary colour, flat (pink in Epic; in the Go Epic themes a pill, black on Light and flat gold on Dark, and the text is the wordmark's Cinzel in gold; grey in Office and Graphite) that reloads; it waits while the Canvas has a change not saved yet (`core/unsaved.ts` `UnsavedWork.canvasDraft`, kept by the Canvas in `ngDoCheck`; the Canvas saves every change at once) or **any other window is open** (an editor keeps its changes until Done; any window may hold typed text; checked every second), since the reload would lose them, and appears once the draft is saved or discarded and the windows are closed (`SwUpdate` VERSION_READY; checks every 30 min and whenever the app comes back to the screen, at most once a minute; an unrecoverable state reloads).

## Data (Firestore)
```
users/{uid}/week/{DAY}         { blocks: Block[] }                 DAY = MONDAY…SUNDAY
users/{uid}/days/{YYYY-MM-DD}  { done: { [taskId]: millis },       the day's task states (local date), status.model:
                                 status: { [taskId]: state } }     done/late keep `done`; late/progress/skipped in `status`
users/{uid}/library/tree       { nodes: LibNode[] }                the task library (Floating Canvas)
users/{uid}/todos/{id}         Todo                                Capture's tasks (todo.model)
users/{uid}/dates/{YYYY-MM-DD} { notes: [{id,name,created,calendar?}], name, created }   the Year's day notes (date-notes, dates.store)
```
- `Todo { id, title, date: 'YYYY-MM-DD'|null, time: 'HH:mm'|null, done: millis|null, created: millis, repeat: Day[], doneOn: { [date]: millis } }` (Gianni): a task with `repeat` days (Mo…Su) comes back every week on those days and is checked per date in `doneOn` (never Finished); a single task open on an earlier day **rolls over** (`overdueTodos`) and leaves its old day: on the Week board it waits at the foot of the screen in a **file folder** (`.overdue-tray`, Gianni: always in sight, and a folder rather than a floating box: a raised tab holds the heading, its foot flaring into the folder's edge, and the folder's body sits on the screen's bottom edge, in `--navy-card`, outlined by a red line, Gianni: so it is noticed and never hidden, up the tab, over it, down and along the folder's top edge to its far right (`--tray-edge`, `--tray-w` 3px (Gianni: thinner; the dark halo stays where there is one): drop-shadows of the folder's shape; a panel chose the red per theme so it keeps at least 3:1 against the page, the day column, the blocks and the folder: the light themes a deep red (#b91c1c, Pink Pop its crimson #be123c), the dark ones a bright red (#ff6b6b, Smoked Citrus #ff5f57) with a 2px dark halo outside it (`--tray-halo`) so it also stands off a yellow block or a plum day; Gianni: down here with the overdue ones, not at the top of the day); it opens as tall as its tasks need, never scrolling inside (Gianni; only past the whole screen), and the board leaves exactly that much room under its last block, `.has-tray`, `--tray-h` measured by a ResizeObserver; its **tab folds it** (Gianni): the tab is a button (`.overdue-head`, `aria-expanded`) that slides the list down out of sight, leaving only the tab and the folder's lip at the foot of the screen, and a second tap slides it back, slowly (1 s, Gianni) (`.overdue-body`, grid rows 1fr ↔ 0fr, inert when folded; a task checked **in the tray** stays in the tray, ticked, at its place and with its label, until the tray is opened again (Gianni: to see what he ticked; `held`, `trayItems`, `trayCheck`, kept only for the day it was checked; its ✓ unchecks it and lets it go back wherever it now belongs). Capture holds **tasks**, one-off to-dos with a day and maybe an hour and a check, **not Activities** (the library). `sanitizeTodo` on the way in.
- **Names (Gianni, as in Epic Manager's nomenclature):** the five levels are shown as **Area → Epic → Feature → Story → Activity** (ES **Actividad**, feminine: la Actividad, una Actividad nueva) ("Activity" replaces Task: Gianni found "Beat" confusing and "Action" unfriendly; "Story" replaces User story; a Story is shaped by its Activities, step by step). Story is feminine in Spanish (la Story). The code keeps `kind: 'story' | 'task'`.
- `LibNode { id, kind: 'area'|'epic'|'feature'|'story'|'task', title, parentId: string|null, color, created?, minutes?, track? }`: `track` (tasks only, `true` or absent, `setTracked`/`trackedIds`) is **Track in Progress** (Gianni: too many Activities to follow them all): only ticked Activities show in Progress; off by default, existing ones included; ticked on the card itself while arranging the week (Gianni: not inside the details, and no 🔥): a checkbox "Track in Progress" / «Seguir en Progreso» on its own centred line under the activity's title, never inside the header (Gianni) (`.t-track`, `setTrack`, saved at once; a plain white box with a thin grey edge and a dark ✓, Gianni: not black (grey inside in Office and Graphite, like their other check boxes); disabled on a card with no library Activity), hidden once arranging ends; saved on the library task so it holds wherever it is planned; `minutes` (tasks only, optional, written only when present: a converted Capture task's minutes; a week card that picks the Activity takes them when they fit its block) and `created` (tasks only, millis, written only when present: Firestore refuses undefined) is when a task was captured or made (Capture, Canvas, Week details); its **paper ages** from then (`paperAge`: fresh under 5 days, parchment 5–20, old stained paper from 21, Epic Manager's textures in `public/paper/`), in the Capture list and the Week's notes and tray, so a neglected task shows it (Gianni); **only loose tasks age, never Activities** (Gianni: activities are events that pass; a task converted into an activity loses its paper, and week cards and the activity picker show the plain colour), and the paper always takes the card's own colour, multiplied into it (`background-blend-mode: multiply` with `--tone`; Gianni: cards on paper had lost their colour); a task without `created` (older, template) keeps its pastel. Five levels, Area → Epic → Feature → Story → Activity (task), each parent of the kind above (`PARENT_KIND`). `parentId` null = an area (the top) or an object waiting in **Free Space** (never an epic; the Canvas shows such Activities in Undefined). Every task exists once in the library; a container can be deleted only when empty, a task always (its week places go on Save).
- `Block { id, name, start: 'HH:mm'|null, end: 'HH:mm'|null, tasks: Task[] }`: the start anchors the first task, later starts cascade by minutes; the end is a hard limit (the tasks' minutes never pass `end - start`).
- `Task { id, title, minutes, color: string|null, active, ref: string|null }`: `color` null = automatic pastel (`blockColors`: FNV-1a of the title, never like the card above, chosen **once** and then kept wherever the card moves: `core/auto-colors.ts` `AutoColors` remembers it on this device keyed by its library `ref`, else its id, in `go-epic-auto-colors`, pruned to cards that still exist; Gianni: moving cards recoloured some; Focus uses the same map). `ref` = the library task this card schedules (one library task can sit in many blocks); the library is the truth for its title and colour (`followLibrary`).
- `firestore.rules`: each user reads/writes only `users/{uid}/**` (week, days, library, todos and dates). Update the rules with any new collection.
- Firestore refuses `undefined`: `WeekStore` sanitizes every block on the way in and out.
- `WeekStore.setBlocks` writes a whole day; an echo of an older local write must not undo a newer one (`pending` queue per day). Keep that when touching the store.

## Conventions
- Standalone components, signals (`signal`, `computed`, `input`, `output`), `@if/@for`; no NgModules, no RxJS state.
- Phones first: tap targets ≥ 40px, inputs 16px (no iOS zoom), safe-area insets, one day at a time ≤ 820px.
- Dialogs are native `<dialog>` with `showModal()`; backdrop clicks via `isBackdropClick`.
- Respect `prefers-reduced-motion`.

## PR Workflow (AI Assistant)
**Every PR that changes what users see adds one short, plain line to `public/changes.json`** (`{ id: next number, v: next version, date, es, en }`, in Gianni's words, no code names; every line of one PR shares its `v`), so the update window tells him what to look for. Two PRs merged one after the other must not reuse an `id` or a `v`: rebase on main and take the next free ones.

The AI assistant **never runs the test suite** itself (typecheck, builds and emulator checks are fine). **GitHub Actions runs it**: `.github/workflows/ci.yml` (Node 22, `npm ci`, `npm test -- --watch=false`, `npm run build`) on every pull request and on main. After pushing: open the PR and comment `@codex review`; fix every Codex finding and ask Codex again; **do not ask Gianni to run tests** (a manual check on his phone only when one is really needed, asked once Codex is clean). Merge only when Codex has no open findings and the **CI check is green on the exact current HEAD**. Angular 22 needs Node ^22.22.3 || ^24.15.0 locally.
