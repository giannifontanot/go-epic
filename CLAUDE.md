# Go Epic - Project Guide

## PR Traceability
Every pull request:
1. ends its title with the **branch session ID** as `- [SessionID]` (the trailing characters of the branch name, e.g. `ofxb07` from `claude/charming-planck-ofxb07`);
2. shows it in the body (`Session: ofxb07`);
3. carries the PR Checklist below.

## Overview
Go Epic is the Week board, Focus mode and Floating Canvas of Epic Manager (`giannifontanot/epic-manager`), rebuilt on Firebase with no server of its own. Only those three screens exist on purpose: no seed editor, no variants, no sync queue. The owner is Gianni.

- **Stack:** Angular 22 (standalone components, signals, new control flow, zoneless), TypeScript strict, Firebase JS SDK 13 (Auth + Firestore), Firebase Hosting, Vitest.
- **Cost:** must stay on the free **Spark** plan: no Cloud Functions, no Cloud Run, nothing that needs the Blaze plan.
- **Offline:** Firestore's persistent multi-tab cache is the offline layer; writes show at once and sync when the network is back. Never add a hand-made sync queue.
- **PWA:** installable app (`public/manifest.webmanifest`, icons in `public/icons/` drawn from `public/icons/icon.svg`, `apple-touch-icon.png` and iOS meta tags in `src/index.html`). The Angular service worker (`ngsw-config.json`, production builds only) caches the app shell so it opens offline; it never caches Firestore/Auth traffic, and navigations to `/__/**` (Firebase's reserved paths) bypass it. `firebase.json` serves `ngsw-worker.js`, `ngsw.json`, the other worker scripts and the manifest with `no-cache` (that rule must stay after the immutable `**/*.@(js|css)` rule: Hosting applies matching header rules in order, the last one wins). When a new version has downloaded, `App` covers the screen (Gianni: impossible to resist): a native modal `dialog.update-overlay` (opened with `openDialog`, so it sits in the top layer above any other open window and traps focus; Esc does nothing), a dark backdrop with a card in the middle, "There is a new version" and one huge button, "Tap to update" / "Presiona para actualizar" (`.update-overlay`, `.update-button` 96px tall, glowing and breathing with a gold halo, `update-glow`; a still halo under reduced motion; grey in Office) that reloads; it waits while the Canvas has an unsaved draft (`core/unsaved.ts` `UnsavedWork.canvasDraft`, kept by the Canvas in `ngDoCheck`) or **any other window is open** (an editor keeps its changes until Done; any window may hold typed text; checked every second), since the reload would lose them, and appears once the draft is saved or discarded and the windows are closed (`SwUpdate` VERSION_READY; checks every 30 min; an unrecoverable state reloads).

## Data (Firestore)
```
users/{uid}/week/{DAY}         { blocks: Block[] }                 DAY = MONDAY…SUNDAY
users/{uid}/days/{YYYY-MM-DD}  { done: { [taskId]: millis },       the day's task states (local date), status.model:
                                 status: { [taskId]: state } }     done/late keep `done`; late/progress/skipped in `status`
users/{uid}/library/tree       { nodes: LibNode[] }                the task library (Floating Canvas)
users/{uid}/todos/{id}         Todo                                Capture's tasks (todo.model)
```
- `Todo { id, title, date: 'YYYY-MM-DD'|null, time: 'HH:mm'|null, done: millis|null, created: millis, repeat: Day[], doneOn: { [date]: millis } }` (Gianni): a task with `repeat` days (Mo…Su) comes back every week on those days and is checked per date in `doneOn` (never Finished); a single task open on an earlier day **rolls over** (`overdueTodos`) and leaves its old day: on the Week board it **floats at the foot of the screen** (`.overdue-tray`, Gianni: always in sight; fixed beside the floating ✎, "Overdue, still open · n" / "Atrasadas, sin hacer", each with a red edge and "from Mon 9", its ☐ and ✎; **today's open tasks whose hour has passed** join it after them (`pastDueTodos`, a repeating one as today sees it, labelled "Today", soonest first; they leave their card so they show once); the list scrolls inside when long and the board leaves room under its last block, `.has-tray`); checking it moves its date to the day it was ticked, so the checked note stays there (`checkTodo`). Capture holds **tasks**, one-off to-dos with a day and maybe an hour and a check, **not Activities** (the library). `sanitizeTodo` on the way in.
- **Names (Gianni, as in Epic Manager's nomenclature):** the five levels are shown as **Area → Epic → Feature → Story → Activity** (ES **Actividad**, feminine: la Actividad, una Actividad nueva) ("Activity" replaces Task: Gianni found "Beat" confusing and "Action" unfriendly; "Story" replaces User story; a Story is shaped by its Activities, step by step). Story is feminine in Spanish (la Story). The code keeps `kind: 'story' | 'task'`.
- `LibNode { id, kind: 'area'|'epic'|'feature'|'story'|'task', title, parentId: string|null, color, created? }`: `created` (tasks only, millis, written only when present: Firestore refuses undefined) is when a task was captured or made (Capture, Canvas, Week details); its **paper ages** from then (`paperAge`: fresh under 5 days, parchment 5–20, old stained paper from 21, Epic Manager's textures in `public/paper/`), in the Capture list, on its week cards and in the activity picker, so a neglected idea shows it (Gianni); a task without `created` (older, template) keeps its pastel. Five levels, Area → Epic → Feature → Story → Activity (task), each parent of the kind above (`PARENT_KIND`). `parentId` null = an area (the top) or an object waiting in **Free Space** (never an epic). Every task exists once in the library; a container can be deleted only when empty, a task always (its week places go on Save).
- `Block { id, name, start: 'HH:mm'|null, end: 'HH:mm'|null, tasks: Task[] }`: the start anchors the first task, later starts cascade by minutes; the end is a hard limit (the tasks' minutes never pass `end - start`).
- `Task { id, title, minutes, color: string|null, active, ref: string|null }`: `color` null = automatic pastel (`blockColors`: FNV-1a of the title, never like the card above). `ref` = the library task this card schedules (one library task can sit in many blocks); the library is the truth for its title and colour (`followLibrary`).
- `firestore.rules`: each user reads/writes only `users/{uid}/**` (week, days, library and todos). Update the rules with any new collection.
- Firestore refuses `undefined`: `WeekStore` sanitizes every block on the way in and out.
- `WeekStore.setBlocks` writes a whole day; an echo of an older local write must not undo a newer one (`pending` queue per day). Keep that when touching the store.

Each grey theme sets the colour tokens and its `--g-*` surfaces (`html[data-theme='office']`, `html[data-theme='graphite']` in styles.css); the rules after them are shared (`html:is([data-theme='office'], [data-theme='graphite'])`): `main` and every `dialog` are drawn in grayscale, so pastels, papers, badges and Canvas objects become greys; cards are one grey a shade apart from the card above (`--g-card`/`--g-card-2`), done cards a pressed grey; in Graphite everything written on a card, note or object reads in the soft light ink; Canvas objects get grey surfaces too (Feature darkest, then Story, then Activity), and so does every other surface with its own light background in Epic (finished and inactive items, Focus cards, the new-activity header, small controls), so the theme's ink always reads on it. A light surface against dark ink (option lists, the selected Copy/Move) uses `--light`, never `--ink`. The Ajustes window itself is not grayed (`dialog.settings-window`), so each theme's little preview keeps its colours; on the Week board the page is not grayed as a whole either, only everything around the now-line (`.board > :not(.week)`, `.task > :not(.now-line)`…), so the line keeps its colour. A new screen or colour needs a look in Office too. The now-line's colour is `--now`: red in Epic, a quiet slate grey in Office and Graphite, red again when Ajustes' **Red time line** box is ticked (`ThemeService.redLine`, `go-epic-red-line`, `<html data-red-line>`, also applied by index.html). A tap on the line's time badge (a button with a 40px hit area) centres the line on screen at once (`centreOnNow`), without marking the card.
- `src/app/shared/`: `WhereCard` (the Where card that is also the chooser: `whereOptions`/`pickWhere`/`whereOf` in library.model) and `ColorWindow` (the small colour window that closes on a choice), used by the Week's activity details.
- `src/styles.css`: all styles (global, Epic Manager palette: navy `#101b42`, cream `#fff4e9`, plum days, yellow jelly blocks, pastel cards, pink `#f4a8b7` primary, teal `#76e0d0` focus).

## Conventions
- Standalone components, signals (`signal`, `computed`, `input`, `output`), `@if/@for`; no NgModules, no RxJS state.
- Phones first: tap targets ≥ 40px, inputs 16px (no iOS zoom), safe-area insets, one day at a time ≤ 820px.
- Dialogs are native `<dialog>` with `showModal()`; backdrop clicks via `isBackdropClick`.
- Respect `prefers-reduced-motion`.

## PR Workflow (AI Assistant)
The AI assistant **never runs the test suite** itself (typecheck, builds and emulator checks are fine). **GitHub Actions runs it**: `.github/workflows/ci.yml` (Node 22, `npm ci`, `npm test -- --watch=false`, `npm run build`) on every pull request and on main. After pushing: open the PR and comment `@codex review`; fix every Codex finding and ask Codex again; **do not ask Gianni to run tests** (a manual check on his phone only when one is really needed, asked once Codex is clean). Merge only when Codex has no open findings and the **CI check is green on the exact current HEAD**. Angular 22 needs Node ^22.22.3 || ^24.15.0 locally.
